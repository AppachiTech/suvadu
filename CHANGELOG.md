# Changelog

All notable changes to this project will be documented in this file.

## [0.5.1] - 2026-10-20

### Added
- **Bookmarks with placeholders** — a bookmark can hold `{{name}}` or `{{name:default}}` (`suv bookmarks add "ssh {{user:root}}@{{host}}" -l box`). Picking it in `suv bookmarks` opens a small *Fill Placeholders* popup with one field per distinct placeholder, in order, each prefilled with its default and with the filled command previewed below; `Tab`/`Enter` moves to the next field (`Shift+Tab` back), `Enter` on the last puts the filled command on your prompt exactly as a plain bookmark is — never run — and `Esc` goes back to the list. Without a terminal, `suv bookmarks get <label|command|id> --set host=db1` prints the filled command; a placeholder left with neither a value nor a default is an error naming it, as is a `--set` for a placeholder the bookmark does not have. A placeholder used twice is asked for once. Names start with a letter or `_` and continue with letters, digits, `_` or `-`; the default is everything after the first `:`, verbatim. `\{{` is a literal `{{`, and anything else in double braces that is not a placeholder — Go templates' `{{.State.Status}}`, `{{` with no closing `}}` — stays as typed. Values are inserted verbatim, so quote them as the shell would need. They are never stored. A bookmark you saved earlier that already has a `{{word}}` meant literally now asks for it; write it as `\{{word}}` to keep it literal.
- **`list_snippets` MCP tool** — read-only and on by default: lists your bookmarked commands, each with its id, label and command, and for a template its distinct placeholders in order with their defaults (`placeholders: user (default: root), host (required)`). `query` filters by command or label text, `parameterised_only` keeps just the templates, and `limit`/`offset` page as every list tool does. It points the agent at `suv bookmarks get <label|command|id> --set name=value` to fill one, which prints the command and never runs it. It can be turned off under Settings → MCP → Tools like any other tool.
- **The AI session timeline and handoff show what changed in git** — when an agent session's git snapshots can be compared, `suv sessions`' timeline header adds `Changed: 3 files, 1 commit` beside the prompt and command counts (on terminals at least 100 columns wide; `3 files+` when a snapshot was capped, `HEAD moved` when the commits could not be read), and the handoff scaffold (`h`) fills *Changed-file evidence* with the HEAD movement, each commit subject and each changed path with what happened to it (up to 50, the rest counted), citing `git-snapshot-start` and `git-snapshot-end` and saying the paths changed in the repository, not necessarily by the agent. The commits are read once when the timeline opens, under the same 2-second limit and the repository's own redaction and exclusions.
- **`what_changed` reports what an agent session changed instead of guessing** — pass `session_id` (`claude-<id>`, `codex-<id>`, `opencode-<id>`, or the agent's own id) and, when the session has git snapshots at its first prompt and a turn end (see the next entry), it answers with `provenance: observed`: the two snapshots' HEADs and branches, the commits made between them with their subjects (read from the repository at that moment, under a 2-second limit, never stored, redacted and filtered by your exclusions; just the two HEADs if the repository or the commits are gone), and every path whose git status changed or that those commits touched — deleted, renamed with its source, untracked, staged — paged with `limit`/`offset` under the response size limit, followed by the session's recorded commands. It says plainly that a path changed in the repository, not necessarily by the agent, and that a path already changed at the start with the same status at the end is not listed. Without both snapshots it reads the session's commands for their likely effect as before, marked observed+inferred, with a note saying why nothing was observed. Asked about a directory and window, it also lists the agent sessions there with snapshots, their HEAD movement and how many paths changed state. `mcp.exclude_dirs` hides a session in an excluded directory and any path beneath one.
- **Agent sessions record which files changed in git** — a Claude Code, Codex, OpenCode or Cursor session working in a git repository now gets a git snapshot at its first prompt and at each turn end (the existing `UserPromptSubmit` and `Stop`/`SessionEnd` hooks, and OpenCode's prompt and `session.idle`; nothing to reinstall): the commit and branch checked out and which paths `git status` reports as staged, unstaged, untracked, renamed, deleted or conflicted — paths only, never contents or diffs. `git` runs only then, never per command, with optional locks and `core.fsmonitor` off and a 2-second limit; outside a repository, without `git` on `PATH` or when it is slow, nothing is recorded and the hook carries on. In a 10,000-file repository a snapshot adds about 30–35 ms to the hook that takes it, nearly all of it `git status`, and a later prompt under 1 ms (Apple M4 Max; see BENCHMARKS.md). Paths matching your exclusions are left out and counted, the rest and the branch are redacted, and at most 500 paths are kept, with the full count. On by default; turn it off with *Record Agent Git Snapshots* in `suv settings` or `[agent] record_git_snapshots = false` — a project's `.suvadu.toml` can turn it off but not on. Schema v15 adds the empty `ai_snapshots` table (at most two rows per session); `suv agent delete-session` deletes a session's snapshots, `suv gc` removes those a day old left without a session, and `suv doctor` charges them to Sessions. Cursor sessions get theirs at `beforeSubmitPrompt` and `stop`, the hooks `suv init cursor` now installs.
- **"Last time this failed, you fixed it with …"** — for a failed command, recall's detail pane now says what fixed it before, most often first (`Last time this failed, you fixed it with: npm install, then reran it (3×)`), and `what_failed` and `learn_from_failures` add a `fixed before (inferred)` line, once per command on a page, marked observed+inferred. It is worked out from history when asked, storing nothing: of the newest 50 failures of exactly that command (Ctrl+C aside), each is paired with the first successful command similar to it among the next 20 of the same session, in the same directory and within 15 minutes — the same program and first argument, or a small edit like `gti status` → `git status` — or, when that is the same command rerun, with the setup step before it (the same program, such as `npm install` before `npm test`, or a package install). Failures and looking around (`cd`, `ls`, `git status`, an editor) are skipped; any other success ends the search with no fix. The README states the rule in full. Each lookup takes 0.6–0.7 ms on a 100,000-command history (Apple M4 Max; see BENCHMARKS.md), and recall makes it once per selected failed command. `mcp.exclude_dirs` applies.
- **Recall and the MCP failure tools say why a command failed** — when a failed command has recorded output (see the next entry), recall's detail pane shows it under an `Output` row, read once per selected command; `what_failed`, `command_status`, `learn_from_failures` (for the latest failure of each command) and the `failures/recent` resource show its last three lines, or all of it with `detail=true`, each behind `| ` and flattened, so it can never forge a row or the trailer, and paged under the response size limit as before. They mark it as the command's own text, not instructions. Without recorded output they now say why it is missing and how to turn it on, instead of claiming the error text is never captured.
- **Keep the end of a failed command's output (opt-in)** — with `[capture] failure_output = true` (*Keep Failure Output* in `suv settings`; off by default), a command that exits non-zero (Ctrl+C's 130 aside) keeps the last 4 KB it printed, wherever Suvadu already has that output: Claude Code's `PostToolUseFailure` error text, Cursor's `afterShellExecution` output, a Codex `PostToolUse` response that carries an exit code and its output text, OpenCode's bash output (rerun `suv init opencode`), and `suv wrap`, which now passes the command's stderr through unchanged while keeping its end. Commands typed in your shell never have it: the zsh and Bash hooks do not stand between a program and the terminal. Escape codes and progress redraws are stripped, and the text is redacted with the command's own per-directory policy before it is cut; an excluded command keeps nothing, and a project's `.suvadu.toml` can turn it off but not on. It is stored beside its command (schema v14 adds the empty `entry_output` table), deleted with it by `suv delete`, carried in JSON and JSONL exports and restored by `suv import`; `suv gc` removes any left without a command, and `suv gc --failure-output` deletes all of it while keeping the commands. Under `suv wrap` with capture on, the command sees a pipe rather than a terminal on stderr.
- **Smart rank learns your habits** — within a match tier, recall's Smart rank (`^S`, on by default) now also weighs frecency: how often and how recently you ran that exact command, with each run counting 16 in its first hour down to 0.25 after a month — the same definition the MCP `suggest_next` tool already ranked by. Twenty runs a day or two ago now beat one run five minutes ago. A command that usually fails (more than half of at least three runs; Ctrl+C is not a failure) is scaled down, to a quarter when it has never succeeded; one failure among many successes changes nothing. A closer textual match still always wins, matching, counts and paging are unchanged, both views rank alike, and Recent rank orders exactly as before. Agent runs count towards a command only while agent commands are shown. Typing costs what it did, except the first keystroke of a recall session, which reads the statistics: 11 ms more for a one-letter query in the Commands view of a 100,000-command history (Apple M4 Max; see BENCHMARKS.md). Schema v13 adds the exit status and executor to an existing index so they are read from it alone; upgrading rebuilds that index once, in about 60 ms for 100,000 commands, and the database grows about 0.3%.
- **Smart rank knows what you usually run next** — after `git add -A`, `git commit` now comes before the `git status` you run far more often. Recall reads, once per session, what followed the newest 500 runs of the shell session's last command anywhere in your history (the next command recorded in the same session, within 10 minutes); a command seen there at least twice is boosted by up to ×3 in proportion to how often it came next. It applies within a match tier, in Smart rank only, and needs the shell hook's session. Turn it off alone with *Sequence Boost* in `suv settings` or `[search] sequence_boost = false`.
- **Each command keeps the git branch it ran on** — every command recorded live inside a git repository — by the zsh and Bash hooks or an agent integration — now keeps the branch checked out in the directory it started in, or the 7-character commit hash of a detached HEAD. Linked worktrees and submodules are followed. It is read from the repository's own files, with no `git` process: about 10–20 µs, so a prompt costs no measurable extra time (Apple M4 Max; see BENCHMARKS.md). `cd ../other` is filed under the branch it was typed on, and a command that switches branches under the branch it switched to. Recall's detail pane shows a `Branch` row and detailed MCP command rows add `branch <name>`. The branch is redacted like command text and never stored for an excluded command. Turn it off with *Record Git Branch* in `suv settings` or `[shell] capture_git_branch = false`; a project's `.suvadu.toml` can turn it off but not back on.
- **A zsh-autosuggestions strategy** — `ZSH_AUTOSUGGEST_STRATEGY=(suvadu history)` makes [zsh-autosuggestions](https://github.com/zsh-users/zsh-autosuggestions) suggest what Up-arrow would recall: the newest command starting with what you typed, AI-agent commands hidden unless `Alt+A` revealed them, falling back to zsh's own history when Suvadu has nothing. The hook does not change your strategy setting; `suv init --help` and the hook's header show the line to add. Each suggestion is one lookup of 5–8 ms p95 at 100,000 commands on an Apple M4 Max, most of it starting the process (BENCHMARKS.md), which zsh-autosuggestions 0.7 fetches asynchronously by default.
- **`suv doctor` says when Up-arrow is no longer Suvadu's** — a plugin loaded after `eval "$(suv init zsh)"` (oh-my-zsh's key bindings, zsh-history-substring-search, zsh-vi-mode, fzf, atuin, mcfly) can rebind Up and silently replace Suvadu's recall, and doctor, running as its own process, could not see that. The zsh hook now checks once per shell, at the first prompt, after all of `~/.zshrc` has run (or after a plugin's own first-prompt hook that comes later, as zsh-vi-mode's does), whether `^[[A`, `^[OA` and the terminal's own Up sequence are still bound to `suvadu-up-arrow`. If one is not, it notes the key and the widget in `up-arrow-binding` in the data directory, and doctor's new *Up-arrow* line warns `bound to up-line-or-beginning-search by something loaded after Suvadu (since …)` with the repair: put the `eval` line last in `~/.zshrc`, then `exec zsh`. A later zsh that finds Up is Suvadu's again removes the note. The check prints nothing and never fails the shell; it costs one subshell per shell start, 0.8 ms median, and starts `suv` only when Up is someone else's, about 5.5 ms (Apple M4 Max; see BENCHMARKS.md). It is skipped when *Enable Arrow Key Navigation* is off, and doctor says so, or that Bash keeps its own Up-arrow history.
- **`hiveagent` finds `hive-agent`** — when a `terms` search (the default) matches nothing, recall tries again ignoring separators — whitespace, `-`, `_`, `.`, `/` and `:` — in both the query and your history, so `hiveagent` finds `hive-agent`, `hive_agent`, `hive.agent`, `hive/agent` and `hive:agent`, and `hive-agent` finds `hiveagent`. The results are labelled `ignoring punctuation (-_./:)` in the results title and `terms (loose)` in the status row, the matched text is marked with the separators inside it, and counting, paging and grouping work as for any search. Exact matches always win: the fallback only runs when nothing matched as typed, and never mixes with exact results. The MCP `search_commands` tool falls back the same way for its whole query and notes it in its response. A new search index (schema v11) answers it: upgrading builds it once (0.7 s for 100,000 commands on an Apple M4 Max), it adds 12–25% to the database's size depending on how long your commands are, and recording a command takes about 25 µs longer (see BENCHMARKS.md).
- **Scroll recall's detail pane** — `Shift+Tab` moves focus into the detail pane when its contents don't fit, and `↑↓`, `PgUp`/`PgDn`, `Home`/`End` (or `j`/`k`/`g`/`G` in vim Normal mode) scroll it. A scrollbar sits outside the pane's border and the title shows the rows in view (`12–32/67`). `Esc`, `Shift+Tab` or any other key returns to the list.
- **Cursor sessions are captured** — `suv init cursor` now also registers Cursor's `afterAgentResponse` and `stop` hooks, so each Cursor conversation is a full agent session (`cursor-<conversation_id>`) in `suv sessions`, `suv agent sessions` and the MCP session tools: prompts, final responses, how each turn ended and the model, with the conversation's commands under the turn they ran in. Cursor's hooks report no token usage, so a Cursor session shows usage as unavailable, never zero, and its capture status says so. Everything goes through the workspace's redaction, exclusions and recording rules; a hook that runs twice stores its event once; `suv agent delete-session` removes it all. Cursor sessions also get git snapshots at the first prompt and each turn end, and the Cursor prompt cache is now redacted before it is written. Rerun `suv init cursor` and restart Cursor.
- **Team skills committed in the repository** — Markdown files in `<repo>/.suvadu/skills/*.md` are skills for that project: optional frontmatter sets `name` (default: the file name; letters, digits, `-` and `_`), `description`, `triggers` and `targets` (`claude-code`, `cursor`, `codex`; default: all). The project is the nearest directory with `.suvadu/skills/`, never above the git repository's root. `suv skills list`, `show` and the TUI include them with origin `repo`, their file path and their trust state, read-only: `edit`, `rm` and `disable` refuse them and name the file to change instead, and Suvadu never writes, moves or deletes the files. Because they arrive with whatever you clone, they are **untrusted** until `suv skills trust` (`--repo PATH`, `--dry-run`, or one name) records a sha256 of each file's content; only then does `suv skills sync`, run from the project root, write them like project skills. A file changed since — after a pull, say — shows as *changed since trusted* and stops syncing until trusted again; `suv skills untrust` takes trust back. A trusted repo skill takes the place of a library project skill of the same name there, and the sync says so. Removing the file or its trust removes the copies Suvadu wrote on the next sync. Files with an invalid name, a symlink, over 256 KB, not UTF-8 or with an unknown target are skipped with a warning naming them. Over MCP, `list_skills`, `get_skill` and `search_skills` include the project's repo skills with `source repo`, file path and trust state; an untrusted or changed one is listed by name and path only and its text is never served. Trust is stored in a new `skill_trust` table (schema v16): hashes only, never the text.

### Changed
- **Prefix search seeks an index instead of reading the whole history** — `suv get --prefix`, which Up-arrow and the zsh-autosuggestions strategy run on every keystroke, took 12–25 ms p95 at 100,000 commands and now takes 5–8 ms, about 1–4 ms beyond starting the process; recall's `prefix` mode fell from 15 ms to 70 µs (Apple M4 Max; see BENCHMARKS.md). Results are unchanged: ASCII case is still folded and `%`, `_` and `\` still match themselves. A new index (schema v12) answers it; it replaces one that another index already covered, so the database grows about 6–8%, and upgrading builds it once, in about 0.1 s for 100,000 commands.
- **Substring search uses the trigram index as intended** — every `terms` and `literal` query used to scan the whole history, because SQLite does not hand a `LIKE … ESCAPE` to the full-text index. At 100,000 entries typical queries now return in well under a millisecond instead of 10–40 ms, with the same results. `fuzzy` no longer runs one scan per letter of the query and is about twice as fast.
- **The risk rules check every command of a line** — `suv guard` and the `assess_risk` MCP tool split chained, piped and wrapped commands (`&&`, `;`, `|`, `sudo`, `env`, `bash -c`, `ssh host`, `$(…)`, `find -exec`) and rate each one. They now catch every spelling of recursive `rm` (`-fr`, `-Rf`, `-r`) and force push (`-f`, `+branch`, `--force-with-lease`), and have rules for `kubectl delete`, `terraform destroy`, `find -delete`, `shred`, `truncate`, `docker system prune`, `git checkout .`/`git restore .`, SQL `TRUNCATE`/`DELETE` without `WHERE`, `crontab -r` and `diskutil erase*`. They no longer block `chmod 755`, `pip install -r requirements.txt` or `./build.sh`.
- **A project `.suvadu.toml` can only tighten privacy** — it can no longer turn redaction off or recording back on, and its `exclusions` and `redaction.extra_patterns` add to your global lists instead of replacing them.
- **`suv update` only installs a strictly newer release**, and refuses a download whose signed version does not match the release it advertises.
- **Suvadu now declares Rust 1.95 as its minimum** (`rust-version`), which its SQLite dependency already required; CI checks it. `cargo install` on an older toolchain now says so up front instead of failing inside a dependency's build script.
- **`suv skills sync` removes what it generated for skills that are gone** — a skill removed with `suv skills rm` or stopped with `suv skills disable` used to leave its `SKILL.md`, Cursor rule and `AGENTS.md` section behind until a separate `suv skills cleanup`. The next sync now removes them, with the same ownership check cleanup uses: only files and blocks that still carry Suvadu's intact marker go, a file edited since is reported and kept, and hand-written agent files are not mentioned at all. `--dry-run` lists them as *would remove*. `suv skills cleanup` still does the same on its own.

### Fixed
- **The session picker keeps your place** — coming back from a session's timeline reset `suv sessions` to an empty query, no filters and the first row of the first page. The query, filters, page and selection now stay as you left them.
- **The session picker's filter popup cancels and rejects cleanly** — `Esc` kept an edited start or end date when that date filter was already applied; it now puts back everything as it was when the popup opened. A date it cannot read (`last tuesday`) used to clear that filter silently while the text stayed in the field; now nothing is applied, the popup stays open on that field, and it says the date can't be read and which forms work.
- **Session timelines say where `q`/`Esc` goes** — a shell session's timeline opened from the session picker or Prompts offered `q/Esc Quit` although leaving returns there, and an AI session's timeline always said `Back`, even when `suv sessions <id>` opened it directly. Both now say `Back` when another screen opened them, `Home` when Suvadu Home did, and `Quit` otherwise.
- **`suv agent dashboard`, `suv agent prompts` and `suv agent stats` exit non-zero when the screen fails** — an error after the screen started (its terminal or output going away, say) was printed but the command still exited 0, so scripts and Suvadu Home's pause on failure could not tell. It now exits 1 with `Error: <screen> stopped: <reason>`; leaving the screen normally still exits 0.
- **Pasting non-ASCII text into recall keeps to the length limit** — a paste into the query, a note or a filter field was limited to 2,000 characters while typing is limited to 2,000 bytes, so pasted accented or CJK text could run to several times the limit. Pastes now stop at the same 2,000 bytes, at the last whole character that fits.
- **Date flags on the command line refuse a date they cannot read** — `suv history`, `suv replay`, `suv search`, `suv sessions`, `suv export` and `suv agent report`/`dashboard`/`prompts` silently ignored an `--after` or `--before` they could not read (`--after "last tuesday"`), and returned everything as if no date had been given. They now stop with `could not read --after "last tuesday" as a date`, list the accepted formats, as the MCP server does, and exit 1. `suv delete --before` gives the same message.
- **Typed text has the same length limit as pasted text** — the `suv skills` search box limited only pastes, and the session picker's search box and filter fields and the alias name being edited in `suv aliases suggest` had no limit. All of them now stop at 200 bytes, at a whole character, as the other screens' fields do.
- **`suv delete --help` no longer shows an example that fails** — its last example, `suv delete "" --before 2024-01-01`, was refused for its empty pattern. It now reads `suv delete "docker" --before 2024-01-01`, Suvadu Home's matching example likewise names the text to delete, and a blank pattern is refused before anything else is checked.
- **`suv aliases suggest` exits non-zero when its screen fails** — like the agent screens, it printed `Error in suggest UI: …` and exited 0. It now exits 1 with `Error: alias suggest stopped: <reason>`; leaving the screen normally still exits 0.
- **Recall's filter popup no longer drops a filter it cannot read** — `Enter` with a date it could not read (`last tuesday`), a tag name that does not exist or an exit code that is not a number turned that field into no filter at all, so recall showed more than asked while the text stayed in the field. Now nothing is applied: the filters already applied stay, the popup stays open on that field, and a red line says what could not be read — the accepted date formats, the existing tags, or that an exit code is a whole number. Editing the field clears it. A blank field still clears its filter.
- **The `workspace` scope keeps to its own directory's case** — recall's `workspace` scope, and the MCP tools that take a project directory (`project_context`, `what_changed`, `learn_from_failures`, `get_stats`, `find_agent_session`), matched the directories beneath it ignoring ASCII case, so on a case-sensitive file system the workspace for `/a/proj` also held commands from `/a/Proj/x`. They now compare paths exactly, and the lookup seeks the directory index instead of scanning it. `mcp.exclude_dirs` still hides a directory however its path is cased, and now also hides the directory itself when it was recorded in another case.
- **Search folds Unicode case rather than only lowercasing it** — a command such as `echo ΟΔΟΣ`, whose last letter lowercases to `ς`, was not found by `σ`, `Σ` or `οδοσ`, and `straße` did not find `STRASSE`. `terms` (for a word with a non-ASCII letter in it), `fuzzy`, the separator-insensitive fallback, recall's ranking and its highlighting now all fold case the same way: lowercase, plus final `ς` as `σ`, `ß`/`ẞ` as `ss`, the `ﬀ ﬁ ﬂ ﬃ ﬄ ﬅ ﬆ` ligatures and long `ſ` as their letters, and the Greek symbol forms `ϐ ϑ ϕ ϖ ϰ ϱ ϵ` as `β θ φ π κ ρ ε`. Highlighting marks the `ß` a match on `ss` came from. A word typed in plain ASCII still folds ASCII case only, as `literal` and `prefix` do, so `STRASSE` does not find `straße`; no locale rules apply, so Turkish `İ` folds to `i` with a combining dot and `ı` matches only itself. A non-ASCII word is also matched about a quarter faster: 20 ms → 15 ms at 100,000 entries on an Apple M4 Max (BENCHMARKS.md).
- **A config file that doesn't load no longer stops agent session capture** — native Codex, Claude Code and OpenCode transcript imports, and the Claude Code, Codex and OpenCode prompt caches, failed outright when `config.toml` or a project `.suvadu.toml` did not parse, so the session or the prompt beside each agent command was lost. They now fall back as recording a command already does — to the global config, or to the defaults with redaction on — and `suv doctor` names the broken file. The Claude Code and Codex prompt caches now also apply the prompt's project `.suvadu.toml`, as the transcript import does.
- **Commands over 64 KB are recorded instead of dropped** — a long heredoc or generated command line was silently not recorded at all. It is now stored cut to 64 KB on a character boundary and ending in `…[truncated N bytes]`. The whole command is redacted before it is cut, so a secret that crosses the cut cannot leave a fragment behind, and exclusion patterns still match against the whole command.
- **Long OpenCode sessions keep being captured** — on every idle the plugin piped the session's whole message history, tool output included, to Suvadu: the work grew with every turn, and once the history passed 16 MB each import was rejected and nothing more of the session was captured. The plugin now sends only what the import stores (message text, model and token counts — no tool output or reasoning), only messages not already imported, in batches well under the cap, and resends a batch the import did not accept. `suv hook-opencode-session` now exits non-zero when an import fails. Rerun `suv init opencode` to install the updated plugin; sessions already captured continue where they left off.
- **Agent commands with megabytes of output are recorded** — Claude Code, Cursor and Codex hook payloads were read only up to 1 MB, so a Bash call whose output pushed the payload past that was lost: Claude Code and Cursor read a cut-off payload that failed to parse, and Codex refused it. Hooks now read up to 16 MB and keep only the fields Suvadu records, skipping the tool's output as they parse it. Past 16 MB the command is still recorded when the agent sent it ahead of the output, as they do.
- **One torn transcript line no longer stops a session's capture for good** — a Codex or Claude Code transcript line that is not valid JSON, such as the remains of an interrupted write, failed every later import, so nothing after it was ever captured. Once a later complete line follows it, the line is now skipped and the import carries on; the import result reports `skipped_malformed_lines` and the session's `capture.known_missing` says how many were skipped. An unfinished last line still waits for the agent to finish writing it.
- **Forked and subagent Codex sessions are captured** — Codex starts a forked or subagent rollout with a copy of the parent's session metadata and history, which every import rejected with "native session ID changed within source", so the child was never captured and its transcript never advanced. The child is now imported as its own session, linked to its parent by `parent_id` (subagents recorded with only a parent thread ID are linked too). The copied parent history is skipped up to the child's first turn, so none of the parent's prompts, answers or token totals are credited to the child.
- **`suv stats` no longer passes recorded command text to a shell** — resolving aliases ran `type <first word>` unquoted through an interactive shell, so a history entry such as `ls;touch${IFS}/tmp/x` was executed. Only plain program names are probed now, each quoted.
- **Bash records the whole line you typed** — the hook stored only the last simple command, so `cd /tmp && ls` was recorded as `ls` and a pipeline as its last stage, with the last stage's duration. An empty Enter no longer re-records a prompt command, and lines typed with a leading space are skipped under `ignorespace`/`ignoreboth`. Loading the hook no longer breaks an existing multi-line `DEBUG` trap.
- **Zsh keeps recording under unusual options** — `OCTAL_ZEROES`, `SH_WORD_SPLIT`, `NO_UNSET`, or a `suv` path containing a space no longer break the hook, and managed aliases load when the data directory's path contains quotes, `$` or backticks.
- **A config file that doesn't load no longer silently stops recording** — recording falls back to the global config, or to the defaults with redaction on, and `suv doctor` names the broken file.
- **Several shells starting together after an upgrade no longer lose commands** — the schema upgrade now runs one process at a time, so they no longer fail with "database is locked" or index history twice.

- **`fuzzy` search now folds non-ASCII case, as the help and README already said** — `terms` compared case with full Unicode lowercasing, but `fuzzy` folded ASCII only, so `suv search --match fuzzy ÉCHO` found nothing where `terms` found `echo écho`. Both modes now fold case the same way; `literal` and `prefix` are unchanged and still fold ASCII only, because SQLite's `LIKE` answers them.
- **The Homebrew install note now covers Bash** — `brew install suvadu` printed only the Zsh hook line and linked the old `www.appachi.tech/suvadu/` homepage. It now gives the Zsh and Bash lines, says to open a new terminal and check with `suv status`, and links the setup guide on suvadu.sh.

## [0.4.2] - 2026-09-24

### Added
- **Explicit matching modes and recall scopes in `suv search`** — how a query matches and where it looks are now two separate, visible controls instead of one fixed behaviour. `--match terms|literal|prefix|fuzzy` (`^X` in the UI) picks the matching rule: `terms` (the default, unchanged — every whitespace-separated word must appear as a substring, in any order), `literal` (the whole query including spaces and punctuation), `prefix` (the command starts with the query), and `fuzzy` (the query's letters appear in order with gaps, so `gco` finds `git checkout`). `--scope all|directory|workspace|session` (`^P` to cycle, `^R` to reset to `all`) picks the history to look at: everything, exactly the current directory, anywhere in the current Git repository or linked worktree, or the current shell session. Every mode narrows candidates in SQL, so none of them falls back to scanning a recent window; a scope that cannot apply here (no repository, no session) says so and falls back explicitly rather than silently. `--here` is now the spelling of `--scope directory`. `--compact` draws recall inline under the prompt instead of taking over the screen. All three have config keys — `search.match_mode`, `search.scope`, `search.compact` — and all default to the previous behaviour.
- **Bash history import** — `suv import --from bash-history <file>` (with `--dry-run`) brings an existing `~/.bash_history` into Suvadu. Timestamped files (`HISTTIMEFORMAT`, `#<epoch>` header lines) keep their real timestamps and their multi-line command boundaries; plain files have neither, so each line is imported as one command with an explicitly synthetic 1970-01-01 placeholder time rather than an invented one. Directory, exit code, duration, and executor are not in a bash history file and are stored as unknown — never a fabricated successful exit. Redaction and exclusion patterns apply exactly as for live recording, the report gives skipped/redacted/malformed counts without echoing any command text, the file is streamed (never loaded whole) and only ever read, and re-importing the same file adds nothing while repeated executions in the source are all preserved.

Atuin has no export command and `atuin history list --format` is lossy (humanised durations, second-resolution formatted times, trimmed commands), so the source contract is the database itself, opened **read-only** and read inside one transaction — no file copy behind SQLite's back and no `immutable=1` assumption, so a running Atuin keeps working. Tested against Atuin 18.0.0–18.22.0 (history schema `20210422143411`–`20260818000000`); an untested migration is rejected with its id and a next step instead of being guessed at. Time, directory, exit code, duration, session, host and author/author-kind are carried over (nanoseconds truncated to milliseconds); Atuin's row id, intent and shell are kept as entry context; rows deleted in Atuin are skipped; and Atuin's `-1` exit/duration is stored as unknown, never as a fabricated success. Redaction and exclusion patterns apply exactly as for live recording, repeated executions are all preserved, re-importing adds nothing, and existing Suvadu records are untouched. Unless `--no-backup` is given, a consistent backup of the Suvadu database is taken first and the exact rollback command is printed; afterwards the report confirms the Atuin file is byte-identical (SHA-256) and that the entries claimed were really written.

A session header reports what Suvadu knows it missed (`known_missing`: a paused window, a directory where capture was off, token counters it could not follow) separately from what it never observes at all (`unverifiable`), so a clean run of exit codes is not mistaken for proof that everything was recorded. A saved summary now shows one of three states instead of a current/stale flag: **CURRENT**, **NEW ACTIVITY** (records were appended and the summary can be extended) and **EVIDENCE CHANGED** (what it was written from changed, so it must be rebuilt). Pressing `h` on a timeline builds a copyable handoff scaffold — goal, attempts, failures, decisions, changed-file evidence, verification state, open questions, next actions, source references — filled only from captured records, with every factual line citing an event or command ID and every judgement left as an explicit fill-in marker. Suvadu invokes no model and writes no prose. The same section list drives a new `prepare_session_handoff` MCP prompt.
- **`suv skills disable` / `enable` / `cleanup`, and a sync you can preview** — a skill can now be stopped from syncing without being deleted (`disable`, reversed by `enable`), and `suv skills cleanup` removes exactly the agent files Suvadu generated for skills that are gone or disabled, reporting anything it will not touch. `suv skills sync --dry-run` names the exact target file and shows a line diff of the managed region only. Every generated region carries a checksum marker of what Suvadu wrote, so a region edited outside Suvadu is reported as a **conflict and skipped** instead of being silently overwritten; `--force` is the way through. `list`/`show` and the TUI preview now show a skill's state, origin and the exact files it syncs to (or why it syncs nowhere), and `rm`/`disable` say plainly that generated files are left behind and name the cleanup step. Only correctness is asserted; latency is machine-specific. [`BENCHMARKS.md`](BENCHMARKS.md) records the method, the first baseline and, explicitly, what is still unmeasured.

### Changed
- **`suv search` control hierarchy** — the shortcut footer is now laid out to the terminal width: accept (`Enter`), cancel (`Esc`), navigation, `Ctrl+F` filters, `Tab` detail and `?` help are reserved first, secondary actions fill whatever space is left, and a hint that does not fit is dropped whole instead of being clipped mid-badge (at 100x30 the footer previously ended in a partial `^`). It now prints two independent facts: **Recording:** (enabled / disabled in config / paused in this shell / both) and **Capture:** (most recent record received *N* ago / hook observed earlier, not verified since / configuration present, capture not yet verified / not yet verified — no captured command found). Only a stored record ever counts as proof; a `SUVADU_SESSION_ID` in the environment is explicitly called out as insufficient. The newest record is shown exactly as stored, so a missing exit code prints `exit unknown` rather than a fabricated `0`, and the exact end-to-end verification sequence is printed on every run.
- **`suv doctor` groups blockers apart from optional integrations** — checks are split into "Required for shell history capture" and "Optional integrations", each check carries its own repair line, and the repairs are collected into one section, so an integration nobody uses no longer looks like a broken installation. A paused shell is repaired with `unset SUVADU_PAUSED`, not `suv enable` (which rewrites the config file and cannot clear a variable `eval $(suv pause)` exported into the running shell); both are printed when both apply. A new "Capture evidence" check reports what the stored data proves, separately from what the config allows. Agent setup is reported per agent as five separate facts — detected process, installed integration, captured commands, native sessions, MCP registration — and an agent that is neither running nor installed is reported as "not in use" with no repair.
- **A risk verdict separates severity, evidence and uncertainty** — `suv guard` and the `assess_risk` MCP tool now report the rule's severity, the span of text that matched it (redacted and length-bounded, so a report can never be the thing that copies a token into a log) and any uncertainty, on separate lines. A literal match such as `rm -rf /srv` settles what the command does; a fetched script, an installed package or an `eval`'d string does not, and the verdict says so. Both state on every path that this is a rule check on the command text, **not a sandbox**. A dangerous command quoted as an argument to a program that only searches, prints or records text (`grep`, `rg`, `git commit -m`, `git log`, `man`, `history`) is no longer flagged, provided the line chains nothing — while coverage grows, because a quote, backtick or opening command substitution now counts as a command boundary, so `bash -c "rm -rf /"`, `ssh host 'rm -rf /srv'` and `VAR=$(rm -rf /x)` are seen for what they are.
- **Documentation now describes the shipped behaviour** — README, `SECURITY.md` and `suv --help` were rewritten against the code rather than against intent: actual matching, ranking and scope semantics (with no frequency or success boost claimed, because none exists); default read-only MCP access, the two write opt-ins, the client restart and which config file the server actually reads; the stored-data inventory, real paths and backup retention; and measured benchmark figures in place of the unsupported "**<2ms** recording overhead, **<10ms** search across 1M+ entries". `CONTRIBUTING.md` gains a release checklist that covers help text, settings, docs, comparison tables, the privacy inventory and the demo recordings together.

### Fixed
- **`suv status` and `suv doctor` no longer read imported history as proof of capture** — both diagnostics classified any recent non-agent row as evidence that the shell hook was working. Importing a single timestamped Bash command dated *now* into a clean machine with no hooks installed therefore flipped `Capture:` to a green check and made `suv doctor` pass "Capture evidence", on the same screen as a warning that `~/.zshrc` did not exist. No command had ever been captured. Rows are now counted by **provenance** — `context.import_source` / `context.imported_at`, the importer's own session namespace (`import-bash-…`, `import-zsh-…`, `atuin-…`) and the JSONL importer's placeholder session hostname — and only a row no importer could have written counts. The verdict is also **scoped to the shell being diagnosed**: a live record from this shell's session proves capture outright; one from another session proves it only while this shell has `suv init` in its rc file; otherwise the diagnostics say a record arrived but not from here. An import-only setup now reports `not yet verified — all N stored shell record(s) came from an import, which is stored history, not capture`, names the rows in a `Note:`, and prints a `To start capturing:` block (`suv init zsh >> ~/.zshrc`, plus a reminder that imported history stays searchable either way) ahead of the unchanged three-step `echo suvadu-capture-check` verification sequence that resolves the state. `suv doctor` carries the same repair on the "Capture evidence" row.
- **A restored JSONL row no longer counts as proof that capture is working** — the importer stamped its placeholder marker only on a session it had to create, so a row restored into a session that already existed looked like a locally captured one: a two-day-old genuine record plus a restore dated now flipped `suv status` to "most recent record received 0 seconds ago, from this shell session" and passed `suv doctor`'s capture check on a machine with no hook installed. Every restored row now carries `context.restored_at`, recording when this database received it, and both diagnostics read it as received by an import rather than observed here. It is deliberately not `import_source`/`imported_at`: the row really did originate on this machine.
- **The zsh importer now records import provenance** — unlike the Bash and Atuin importers it wrote no `context` at all, so a zsh-imported row was indistinguishable from one the live hook recorded. Every row it writes now carries `import_source=zsh-history`, `imported_at`, `timestamp_source` (`file`, or `synthetic` for a plain history file that carries no times) and `unknown_fields`. Rows imported by an earlier version have no such context and are still recognised by their `import-zsh-…` session.
- **`get_agent_session` pages over records it can read, not raw rows** — it limited `ai_events` rows in SQL, skipped the ones it could not decode afterwards, and then decided from what was left whether more existed. A single malformed row therefore consumed the look-ahead slot: with one bad record followed by four good ones, `limit=2` returned two events with `next_event_offset: null` and `session_complete: true`, so a client following the documented contract silently never received the last two. Offsets now count readable records — the same unit as `events_total`, the header's `event_count` and a summary's `resume_event_offset`.
- **A saved AI-session summary is fingerprinted over readable events, not raw rows** — `ai_session_prefix_hash` sliced `ai_events` with `LIMIT ?2`, but the count it was given (`source_event_count`) counts *readable* records, the same unit as `event_count`, `events_total` and `resume_event_offset`. In a session holding a record suvadu cannot decode, the fingerprint therefore stopped short of the last readable events the summary was actually written from, and a later change to one of them left the checkpoint reporting `NEW ACTIVITY` / `incremental_safe` instead of stale. Unreadable rows are now skipped before the window is cut, the same way `get_agent_session` pages them (see the event-pagination fix above). Command rows are unchanged: an unparseable `context` degrades to null rather than dropping the row, so their raw count is the right window.
  - **Effect on summaries saved before this fix:** the stored `source_prefix_hash` of a summary that was saved *while its session already contained an unreadable event row before the last covered event* no longer matches the recomputed one, so that summary reads as `INVALIDATED` (`stale: true`, `incremental_safe: false`, no `resume_event_offset`) and must be rebuilt from the evidence rather than extended. Its text, agent, model, source ids and timestamps are untouched, and nothing is deleted. Summaries in sessions with no unreadable rows — the overwhelming majority — hash identically and are unaffected.
- **An Atuin `intent` can no longer smuggle a secret past redaction** — only the command went through the recording policy, so free-form metadata Atuin stores beside it (`intent`, `author`, `shell`, `hostname`) was copied verbatim into the entry's `context`. Importing a perfectly clean `echo normal` whose `intent` held a GitHub-token-shaped string stored the whole token, and the import reported **zero** redactions. Every free-text field now goes through the same redaction and exclusion patterns as the command before it is persisted or previewed: a match is rewritten, a field an *exclusion* pattern matches is withheld entirely and named in `context.withheld_fields` rather than quietly vanishing, and the report counts both (`Redacted before storage: N row(s); M metadata field(s) rewritten or withheld`). A row whose only offending text was in metadata now counts as redacted instead of looking clean.
- **The Atuin importer no longer drops distinct executions** — it added an occurrence ordinal to each millisecond timestamp to separate sub-millisecond repeats and then deduplicated on (command, adjusted time), so the invented time could collide with a genuinely different execution: three `true` runs at `…000000000`, `…000000001` and `…001000000` ns previewed as three imports, stored **two**, reported one "Already present" and lost source row `2`. Idempotency is now decided by the row's own Atuin `id`, already stored as `context.atuin_id`: every `atuin_id` previously imported is read once before the pass, and a row is skipped only when its own identity is already present. Times are therefore never invented — `started_at` is the source timestamp truncated to milliseconds and nothing more — so two executions inside one millisecond both survive, an unrelated Suvadu row that happens to share a command and a millisecond is no longer mistaken for one of them, and a dry run reaches exactly the same verdict as the apply.
- **An Atuin import now honours each source directory's project policy** — the importer loaded the global configuration once, so a row whose `cwd` contained a `.suvadu.toml` with its own `redaction.extra_patterns` and `exclusions` imported both the matching secret and the excluded command. Policy is now resolved per source directory exactly as live recording resolves it for a command's own `cwd` (global config plus the nearest `.suvadu.toml` above that directory, cached per directory). A row whose directory Atuin did not record, or which does not exist on this machine, falls back to the global config, and an unreadable overlay stops the import rather than silently importing under a looser policy. The Bash and Zsh importers cannot do this — their history files carry no directory — and `SECURITY.md`'s per-path table now says so per path instead of claiming a flat "yes".
- **Typed interactive search now matches across the whole history** — `suv search`/`Ctrl+R` fetched the newest 5,000 eligible rows and then matched them in memory, so an exact match older than that vanished from the UI while still sitting in the database. Candidate selection now happens in SQL over the entire eligible history; the 5,000 limit remains, but it bounds how many *matches* are ranked, not how much history is searched. SQLite's `LIKE` folds case for ASCII only, so a query token containing non-ASCII characters used to miss a command differing only by the case of a non-ASCII letter; those tokens now go through a new `suvadu_contains_ci()` SQL function using Rust's Unicode lowercasing, while ASCII tokens keep using `LIKE` against the trigram index.
- **Interactive search reports a result count it can actually page to** — the 5,000-match ranking window was also used as the *total*, so a broad query claimed exactly 5,000 results, refused to go past page 100, and put any older eligible match — including an exact one — out of reach. Both the ordinary and the unique branch did this. Matching and counting now finish in the database for every mode, so the count is the true number of eligible matches and every page it implies can be opened. Ranking is the only part that stays bounded: the newest 5,000 matches are ordered by relevance and anything beyond them is paged newest-first, because a relevance order computed from part of a result set is arbitrary. A count is never reported that cannot be paged to.
- **`--query` now goes through the same pipeline as typing** — starting recall with a query loaded the SQL candidate set straight into the UI, skipping the eligibility and ranking stage every other interaction uses. In `fuzzy` mode SQL only checks that each distinct query character occurs *somewhere*, so `suv search --query gco --match fuzzy` could return `ocg` while typing `gco` returned `git checkout`. Startup, typing, editing, mode and scope changes and pagination are one pipeline with one answer.
- **`fuzzy` keeps its own ordering rule** — the subsequence check only ran when nothing matched literally, so a query whose words each appeared slipped past it: typing `checkout git` in `fuzzy` mode returned `git checkout`, which the documented "letters in order, gaps allowed" rule does not accept. Mode eligibility is now decided independently of how well an entry ranks, and SQLite evaluates the rule itself through a new `suvadu_subseq_ci()` function that shares its implementation with `MatchMode::matches`. `terms` still matches words in any order — that difference is the point of having both.
- **An upper-case query in `terms` mode matches case-insensitively, as documented** — the relevance scorer treats a capital letter as a request for a case-sensitive match, and it was also acting as the filter, so `GIT` found nothing while `git` found everything. Ranking no longer decides eligibility; an entry with no relevance signal is ordered last, not dropped.
- **A field search on the executor matches its name, not only its type** — the database matches that field as `<type> <name>`, but the in-memory ranking looked at the type alone, so a row that matched on the name was counted by the database and then dropped while ranking: searching the executor field for `e` reported `History (1-1 / 2)` and the second row could not be selected, while `literal` mode (which does not re-rank) showed both. One definition of the text a field search matches now serves both stages.
- **`Enter` on a search with no results leaves recall** — it previously did nothing at all, so a query that matched nothing could only be escaped with `Esc`. Accepting when there is nothing to accept now closes recall with no selection and the shell keeps its buffer. `Enter` with results present but no row selected is unchanged.
- **`suv search --compact` works when the shell widget runs it** — inline recall has to know where the cursor is, and crossterm asks by writing the request to **stdout**. The shell integration runs recall inside a command substitution so it can put the chosen command on your prompt, which makes stdout a pipe: the request never reached the terminal, and compact recall died with "The cursor position could not be read within a normal duration" every time. Recall now asks `/dev/tty` directly, so the question and its answer stay on the terminal whatever stdout is connected to. A terminal that will not answer no longer breaks recall either — it says so in one line and opens the full-screen surface instead, and a command selected there still reaches the shell, where the inline teardown previously asked a second time, failed, and discarded the selection.
- **`suv skills sync` no longer deletes instructions written below its marker** — the ownership check only looked at the text *above* the checksum marker, so anything appended under it was invisible to drift detection and to the `--dry-run` diff, while the write replaced the whole file: a hand-written paragraph at the bottom of a generated `SKILL.md` or `.mdc` rule was previously destroyed silently, without a conflict and without `--force`. Suvadu's block ends at the marker's own `-->`, so anything after that — including text typed after it on the same line — is now treated as somebody else's: the file is reported as a **conflict** and left alone, the preview shows that text as removed rather than promising a clean "would update", and `--force` remains the only way through. `suv skills cleanup` uses the same complete check and now leaves such a file in place instead of deleting it. Codex's `AGENTS.md` was never affected — Suvadu owns only a marked block there — and text outside that block is still preserved untouched.
- **A project-scoped skill no longer uninstalls the global skill of the same name** — `suv skills cleanup` derived the expected *global* destinations from the skills resolved for the current project, where a project-scoped `alpha` shadows global `alpha`; the global one therefore looked orphaned, and running cleanup from that project deleted the global `~/.claude/skills/alpha/SKILL.md` and stripped the global Codex managed block, while the library still listed both skills as active. Every other project lost the skill. Global destinations are now decided from the active global library entries, before any project shadowing; a global file is still removed once the global skill itself is gone or disabled.
- **`suv skills cleanup` no longer calls a run clean when it preserved edited files** — it ended with "Nothing to clean up — every generated file still has an active skill behind it" whenever it removed nothing, including when it removed nothing *precisely because* a generated file had been edited outside Suvadu and deleting it would have destroyed that edit. The per-file line said so and the summary contradicted it; the summary now reports that outcome as its own and points at the per-file reasons.
- **Complete and consistent MCP settings** — the MCP tab in `suv settings` listed only 15 of the 21 default tools and seven of the eight resources, and exposed neither write opt-in, so enabling saved session summaries or skill proposals meant hand-editing `config.toml`. Tool and resource metadata now lives in one shared catalog (`src/mcp/catalog.rs`) that drives both the server's advertisement and the settings controls, with tests asserting the two sets are identical by name rather than by an expected count. `Allow Saved Session Summaries` and `Allow Skill Proposals` are now rows on that tab (still off by default), each tool row shows its *effective* state and the reason it is off instead of two switches that can disagree, and the tab states that the MCP server reads its configuration at startup so the client must be restarted for a change to take effect. Saving from the settings UI also preserves keys the running build does not know about, so a hand-edited or newer-version `config.toml` is no longer silently trimmed.
- **`suv update` on macOS downloaded the wrong build, or nothing at all** — the updater derived the archive name from the architecture alone, exactly as the install script used to. On Apple Silicon it requested `suv-macos-aarch64-…`, which is never published, and the update failed; on an Intel Mac it requested the unsuffixed archive, which is the arm64 build. Linux was correct only because there the unsuffixed target really is x86_64. The updater, the install script and the release workflow now resolve one set of names, and tests hold the three to each other.
- **Input is no longer lost while compact recall opens** — an inline viewport has to ask the terminal where the cursor is, and that question used to be answered by reading `/dev/tty` directly, which swallowed anything typed in the same moment. Typing straight into `Ctrl+R` lost its first characters and searched for something nobody typed; a bracketed paste or an editing key was dropped whole. The question now goes to the terminal while crossterm does the reading, so every other event it parses — typing, a paste, Backspace, arrows — is queued and delivered to recall in order, with paste framing and UTF-8 boundaries intact. Input typed while a terminal that never answers is timing out survives too, and arrives in the full-screen surface recall falls back to.
- **A command accepted in compact recall survives a terminal that stops answering** — erasing the inline viewport asks for the cursor position a second time, and that question was allowed to fail the whole command, so a cleanup problem discarded a command the user had already chosen and left the prompt empty. Cleanup is best effort now and the selection is returned either way.
- **`curl … install.sh` on macOS downloaded the wrong build, or nothing at all** — the installer mapped architecture to an archive suffix without regard to the operating system, but the release workflow leaves each OS's primary target unsuffixed and they differ. On Apple Silicon it requested an archive that is never published (HTTP 404); on an Intel Mac it downloaded the arm64 build. Linux matched by coincidence. OS and architecture are now resolved together, a failed download explains itself and points at Homebrew and Cargo, all four supported combinations are checked against what is actually published, and the release workflow now publishes `scripts/install.sh` itself — the served copy had been uploaded by hand and drifted behind the repository.
- **Pasting a wrapped command into `suv search` no longer makes it unmatchable** — pasted newlines and tabs were dropped rather than turned into spaces, so `cargo test\n--offline` became `cargo test--offline`. They now collapse to a single space and the result is trimmed.
- **`resolve_current_agent_session` never resolves "this session" without a directory to match** — it previously fell through to the recent-list filter even when no working directory could be determined, so a single captured session from an unrelated project resolved as `source=unambiguous_cwd` although no directory was ever compared. No directory now means no resolution, more than one match is always the user's choice, a truncated candidate list says so, and a directory-only match carries its match reason and a verification note.
- **A recorded command can no longer forge an MCP row or repaint a terminal** — command text is arbitrary bytes someone typed, so a newline inside one could split a response row in two or append a second `---` trailer an agent would read as the real one, and an ANSI escape inside one reached whoever printed the response. `echo $'\e[2J'` is a real command to have run, so this needed no attacker. Control characters are now flattened to a single space before the length limit applies.
- **`suv doctor` no longer creates the database as a side effect** — it reports "not created yet" instead of silently initialising one, and `db::backup_dir_path` reports the backup location without creating it.
- **`suv uninstall` prints the real paths** — it listed an invented `~/Library/Application Support/suvadu/` (the bundle identifier is `tech.appachi.suvadu`) and a Linux hint that omitted `~/.local/share/suvadu`. It now lists the actual config and data directories resolved from `project_dirs()`.
- **`suv settings` no longer drops config keys it does not know** — saving one field re-serialized the whole config, silently discarding any key the running build has no struct field for, such as a hand-added key or one belonging to a newer version. Saves now merge over the existing file's TOML tree.

### Security
- **Session summaries saved over MCP now go through redaction and exclusions** — a summary was stored exactly as the agent wrote it. A summary is derived text: an agent that read a session can restate a secret the redactor caught on the way in. `save_session_summary` now applies the configured policy, **refusing** text that matches an exclusion rather than silently trimming it, and `suv mcp-serve` installs the user's redaction, exclusion and risk settings at startup.
- **The Zsh importer now applies redaction and exclusions like every other ingestion path** — `suv import --from zsh-history` stored whatever the file contained, so a secret already sitting in `~/.zsh_history` was copied in verbatim and configured exclusion patterns were never consulted. Importing could therefore store text that typing the same command would have redacted. It now runs the same recording policy as live recording and the Bash importer, and reports excluded/ignored/redacted counts in both the dry run and the real import. `SECURITY.md` carries a per-path table of which ingestion paths apply which rule.
- **`suvadu://skills/index` hides skills scoped to an excluded directory** — `list_skills` already did, but the resource mirroring it still returned the skill's name, scope and description under the same configuration, and a skill's scope *is* the path the exclusion exists to hide. The resource now applies the same visibility policy as the tool.
- **Capture diagnostics no longer name a directory that exclusions hide** — `capture.known_missing` interpolated directory names straight out of stored capture gaps, so `get_agent_session` answered "Records from /private-project were skipped while capture was off there" even when `mcp.exclude_dirs` covered that path: the exclusion hid the records and disclosed where they came from. An excluded gap is now counted rather than named — "Records from 1 directory were skipped while capture was off there; the path is withheld by `mcp.exclude_dirs`" — so the reader still learns the history is incomplete.

  `@` are prefixed to neutralize spreadsheet formula execution.
- Bounded input fields: 2,000 characters in search, 500 in settings, 256 for
  session IDs.

  - `session_ui/` — new module with picker and timeline sub-modules.

### Fixed

- **Shell hooks** — Doubled braces in executor detection caused `bad
  substitution` errors on `source ~/.zshrc`.
- **Arrow-key navigation** — Failed commands were incorrectly hidden when
  cycling through history with arrow keys.
- **Negative durations** — Commands with clock skew or out-of-order timestamps
  no longer produce negative duration values (saturating arithmetic).
- **UTF-8 byte-slicing** — Four locations in agent UI that sliced strings at
  byte boundaries instead of character boundaries, causing panics on
  multi-byte characters.
- **Fuzzy search threshold** — Miscalculated minimum score allowed irrelevant
  matches to appear in results.
- **Config cache TOCTOU** — Race condition between checking file mtime and
  reading content.
- **Timeline underflow** — Empty sessions caused arithmetic underflow in
  timeline calculations.
- **Alias name collision** — Removed arbitrary suffix limit of 99 that
  prevented generating unique alias names for similar commands.
- **Filter popup** — Crashed or rendered incorrectly on terminals smaller than
  the popup dimensions.
- **Division-by-zero** — Stats heatmap and percentage calculations guarded
  against empty datasets.
- **Thread-unsafe env access** — `std::env::set_var` calls replaced with
  thread-safe alternatives.
- **LIKE escaping** — Special characters (`%`, `_`, `\`) in search patterns are
  now properly escaped for SQLite LIKE queries.
- **REGEXP cache** — Eliminated `unwrap()` on regex compilation cache that
  could panic on invalid patterns.
- **Nanosecond timestamps** — Timestamps from tools reporting in nanoseconds
  are now normalized correctly.
- **Quote-aware shell chaining** — Risk assessment now correctly handles
  `&&`, `||`, `;` inside quoted strings rather than treating them as chain
  operators.
- **LIMIT injection** — Page size values are now validated before interpolation
  into SQL queries.
- **Ctrl+key fallthrough** — Ctrl+key combinations no longer trigger unintended
  actions in search input.
- **Bookmark `created_at`** — Timestamp now set at creation time instead of
  defaulting to zero.
- **Streaming export** — Large exports no longer load the entire dataset into
  memory.
- **Display-width truncation** — Uses Unicode display width so CJK and emoji
  characters are measured correctly instead of by byte count.
- **Atomic file writes** — All configuration and data file writes use
  `tempfile::NamedTempFile` + `persist()` to prevent corruption on crash or
  power loss.
- Eliminated all production `unwrap()` calls — replaced with proper error
  propagation or safe defaults.
- Graceful handling of clipboard, config parsing, and JSON serialization
  errors.

### Performance

- **Cached `ProjectDirs`** via `LazyLock` — eliminated repeated filesystem
  lookups on every command ingestion.
- **Config mtime caching** — config file is only re-parsed when the file's
  modification time changes.
- **Reordered early exits** in the ingestion hot path — exclusion checks and
  validation run before any database work.
- **Streaming export** — CSV/JSONL exports write row-by-row instead of
  collecting the entire dataset.
- **Stats query indexes** — Added database indexes for the most common
  analytics queries.
